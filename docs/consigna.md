📐 SEGUNDA ENTREGA — DISEÑO Y MÓDULOS
🎯 Esta instancia tiene como objetivo validar el diseño de la base de datos y el listado de módulos que desarrollará el equipo, junto con la estructura inicial del repositorio. Es la entrega que otorga la condición de Regular en la asignatura.

✅ Todo lo presentado aquí debe estar aprobado por el tutor. Sin esta aprobación no se puede continuar con la siguiente etapa.

🚨 Importante: dónde se entrega y para qué sirve la tarea del campus
La entrega real del contenido se realiza subiendo todo al repositorio único de GitHub declarado en la entrega 1. Ahí es donde el tutor revisa el trabajo.

La tarea que figura en el aula virtual tiene una única función: dejar asentada la devolución en la libreta de calificaciones del campus. No se sube el trabajo ahí.

📐 Etapa de análisis y diseño (todavía sin código)
En esta instancia todavía no se debe subir ningún código ni implementación (ni Frontend, ni Backend, ni lógica de negocio). Estamos en etapas de análisis y diseño del proyecto: lo que se entrega son esquemas, diagramas, listados y documentación. La codificación comenzará recién después de que esta entrega sea aprobada por el tutor.

⏳ Fecha máxima de entrega
27/09. La entrega se considera efectiva cuando todo el contenido requerido esté subido y actualizado en el repositorio único de GitHub declarado en la 1.ª entrega.

📦 Contenido obligatorio en el repositorio
🗄️ Esquema de Base de Datos: Diagrama entidad-relación (si es relacional) o esquema de colecciones/documentos (si es documental). Debe incluir tablas/colecciones, campos, tipos de datos, claves primarias y foráneas, relaciones e índices principales. Subido a /database o /docs.
🧩 Listado de Módulos: Enumeración de todos los módulos funcionales que se desarrollarán (ej. autenticación, gestión de usuarios, ABM de productos, reportes, etc.), con una breve descripción de cada uno y su prioridad. Subido a /docs.
🏗️ Arquitectura del proyecto: Descripción de la arquitectura elegida (MVC, capas, microservicios, etc.), tecnologías definitivas y justificación de las decisiones técnicas. Subida a /docs.
📁 Estructura del repositorio: Carpetas ya creadas y organizadas según la arquitectura (ej. /frontend, /backend, /database, /docs), con archivos base y README actualizado.
📚 Documentación en el repo: Todos los esquemas, diagramas y listados deben estar subidos al repositorio dentro de la carpeta correspondiente (ej. /docs o /database).
